# Contributing

Contributions are welcome in documentation, tests, data tooling, evaluation, and safety review.

1. Open an issue or discussion for substantial changes.
2. Keep changes focused and add tests for behavior changes.
3. Do not include secrets, personal data, private partner material, or data without documented redistribution rights.
4. Do not mark a dataset record as approved without the required independent review evidence.
5. Run `python -m pip install -e ".[dev]"`, `pytest`, and `ruff check .` before opening a pull request.

Pull requests must explain the problem, the change, how it was tested, and any impact on data rights or agricultural safety. A passing CI run is required before merge.
